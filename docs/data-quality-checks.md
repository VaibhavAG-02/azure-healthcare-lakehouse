# Data quality checks

## Referential integrity

Every child table (conditions, medications, procedures, immunizations, allergies, claims) is validated against the `patients` table before being written to Silver. The check uses a `left_anti` join to find rows with no matching patient, then asserts the count is zero — the pipeline fails the run rather than silently persisting orphaned data.

Result on the validated dataset (1,180 patients): **0 orphaned records** across all 6 child tables.

```
patients_silver: 1180 rows
conditions_silver: 44819 rows, 0 orphans
medications_silver: 67726 rows, 0 orphans
procedures_silver: 205117 rows, 0 orphans
immunizations_silver: 16819 rows, 0 orphans
allergies_silver: 1100 rows, 0 orphans
claims_silver: 145006 rows, 0 orphans
```

This output was captured on Databricks Free Edition while validating the transform logic before deploying to Azure. The identical code (same assertion checks) subsequently ran successfully on Azure as part of the `silver_transform` task in the orchestrated pipeline — see `docs/screenshots/02_databricks_job_run.png`, where that task shows Succeeded. An assertion failure in this code would raise an exception and fail the task outright, so a green status on Azure confirms the same 0-orphan result held there too.

Note: `claims.csv` has a differently-named foreign key column (`PATIENTID`) than the other five child tables (`PATIENT`). This was caught during development when the join failed on `claims` under Spark Connect's strict attribute resolution ([ATTRIBUTE_NOT_SUPPORTED] error) - Spark Connect requires exact column-name matches for dot-notation access, unlike classic Spark's more permissive attribute lookup. Fixed by mapping each table to its correct foreign key column explicitly rather than assuming a uniform schema.

## De-identification (HIPAA Safe Harbor)

Columns dropped from `patients` before it reaches Silver/Gold: `SSN`, `DRIVERS`, `PASSPORT`, `FIRST`, `LAST`, `MAIDEN`, `ADDRESS`, `BIRTHPLACE`, `ZIP` (replaced with 3-digit `zip3` prefix). Date of birth is converted to `age` rather than retained as an exact date. A SHA-256 hash (`patient_hash`) replaces the raw `Id` as the join key used downstream.

## Deduplication

All child tables are deduplicated (`dropDuplicates()`) before writing to Silver, guarding against duplicate ingestion on reruns.

## Row count reconciliation

Source: 1,180 patients (1,000 living, 180 deceased) generated by Synthea.
Bronze: 1,180 rows in `patients` (matches source, no loss at ingestion).
Silver: 1,180 rows in `patients_silver` (no records dropped during de-identification).
Gold (initial SCD2 load): 1,180 rows, all `is_current = true`.
Gold (after simulated 5% attribute change, SCD2 merge test): 1,180 `is_current = true` + ~51 `is_current = false` (closed-out prior versions) = ~1,231 total rows. Verifies the merge correctly preserves history rather than overwriting it.
